# Doppler orbit fitting: a synthetic demonstration

The [script](sputnik2.py) builds on the range-rate idea in
[sputnik1.py](sputnik1.py), adding a rotating ground station, a simplified
two-body orbit model, and a least-squares fit of an initial satellite state.
Despite its historical labels, it does not process Sputnik 1 recordings or
reproduce the orbit determination performed at the Johns Hopkins Applied
Physics Laboratory (APL). Its observations are generated by the script itself.

## Historical connection

Sputnik 1's October 1957 radio beacon gave observers a signal whose frequency
shifted as the satellite moved toward and away from them. This Doppler shift
measures motion along the line of sight (range rate), rather than directly
providing a satellite's full position. William Guier and George Weiffenbach
published a theoretical analysis of Doppler radio signals from Earth
satellites in 1958. Their later paper treated the complementary navigation
problem: using satellite Doppler measurements to determine a receiver's
position. That work became part of the development of the U.S. Navy's Transit
satellite navigation system. The papers provide historical context for the
idea explored here, not documentation of this program's algorithm
([sources](#historical-sources)).

The distinction between the two problems matters. Orbit determination uses
observations to estimate the satellite's path; Doppler navigation assumes a
known satellite path and estimates the receiver's location. This script
instead creates a synthetic path and fits a six-value initial state to
synthetic Doppler observations, with the carrier frequency held fixed. It
does not implement either complete historical procedure.

## What the script computes

### Station and constants

The script defines Earth's gravitational parameter, an Earth radius, rotation
rate, and the speed of light. Its station model uses a fixed latitude of
39.16 degrees and rotates that point about Earth's z-axis at the specified
rotation rate. Although a longitude of -76.90 degrees is declared, calls to
the station functions omit the `lon_0` argument, so the default longitude of
zero is used. Thus the code does not actually place its modeled station at
the stated APL longitude. It also uses a spherical Earth rather than a
geodetic station model.

### Orbit model and Doppler measurement

`propagate_orbit` takes an initial position and velocity vector. It computes
specific orbital energy, an eccentricity magnitude, and a mean motion, then
uses five Newton iterations to solve Kepler's equation at each requested
time. It constructs approximate satellite positions and velocities from
those quantities.

For each time, the script subtracts the station position from the satellite
position to get the line-of-sight vector `rho`. It projects relative
satellite/station velocity onto that vector to get range rate, then uses the
first-order Doppler approximation

```text
f_pred = f0 * (1 - range_rate / c)
```

The sign convention makes the modeled received frequency rise as the
satellite approaches and fall as it recedes.

This propagation is only illustrative, not a rigorous Keplerian state
propagator. In particular, it does not rotate orbital-plane coordinates
using an orthonormal perifocal-to-inertial transformation: it combines
normalized initial position and velocity directly as coordinate axes. Its
velocity calculation, `cross(h, pos) / |pos|^2`, is purely tangential and
omits the radial component present on most points of an eccentric orbit.
Consequently, its positions and velocities should not be treated as a
physically accurate ephemeris.

### Synthetic data and least-squares fit

The script sets a six-component initial state (`true_pos` and `true_vel`),
uses the same `propagate_orbit` function to generate a 15-minute arc of 45
frequencies, and adds Gaussian noise with an 8 Hz standard deviation. The
random generator is not seeded, so the observations and fit vary from run to
run.

It then gives `scipy.optimize.least_squares` a different six-component
starting state and minimizes the frequency residuals. The assumed carrier
frequency is passed as a fixed argument; it is not one of the fitted
parameters. The optimizer returns an estimated initial state, from which
`state_to_elements` calculates only the semi-major axis and inclination.
These are compared with the same two quantities computed from the synthetic
input state. The code does not calculate all six classical orbital elements.

Because synthetic observations and predictions share the same approximate
propagator, the fit is a demonstration of optimization against a self-
generated model. Any apparent agreement is not evidence that the propagation
is physically accurate or that the fit recovers Sputnik 1's orbit. The
initial-state comments and printed “True” values refer only to this
simulation.

The plot labels also overstate what the program does: “Station Transcriptions”
are generated noisy samples, and “UNIVAC Reconstructed Path” is the output of
SciPy's `least_squares` on the current machine, not a historical UNIVAC result.
The curve plots add the model residual (`predicted - observed`) back to each
observation, which yields the model-predicted frequencies. Treat these labels
as remnants of the exploratory example, not descriptions of the data source.

## Reading the history through the model

The durable connection to the historical work is the measurement equation:
frequency shift contains information about line-of-sight motion. To turn a
sequence of those measurements into an orbit or a receiver position requires
a model of the satellite trajectory, observer motion, timing, and measurement
errors. The 1958 and 1960 papers below document how Guier and Weiffenbach
developed the Doppler analysis and navigation idea. This program is a small
teaching sketch of the numerical pattern—predict measurements, compare with
observations, adjust parameters—not a transcription of their equations,
hardware, or results.
